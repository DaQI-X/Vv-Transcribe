# 做一条合格字幕

这一份是给 agent 看的操作手册。它只讲两件事：**怎么把稿子出成能上屏的字幕**，以及**判据是什么、判据从哪来**。

写它的人把每条说法都对着 `src/utils/subtitleSpec.ts`、`src/utils/subtitleParse.ts`、`src/data/subtitle-presets/*.json` 和 `electron/cli/vv.ts` 核过。下面这些数字不是行业传说，是这个应用真的会拿去判的那几个数；它们住在档位文件里，改文件不改代码，所以**下次跑出来的数与这里不一致时，以报告为准**——`--json` 看 `preset.rules`（归一化后的整份档位，每条带 `cite`/`source`），文本报告看末尾那张「这一档每条阈值的来路」。

## 最短路径

```
素材.mp4
  → transcribe（format=json，拿回段落数组）
  → 改 text 和起止时间（一次改一段，别整轴重排）
  → export（format=srt，用它出盘而不是自己拼）
  → check（--preset broadcast-cn --fps 25）
  → 报告里 findings 一条一条改回去，再 check 一次
```

命令行那一头只有两条子命令，改稿那一步不在命令行里：

```sh
vv transcribe 素材.mp4 -f srt -o 交付.srt         # 要应用开着；一步出盘
vv check 交付.srt --preset broadcast-cn --fps 25  # 判，跟应用开没开着无关
```

要中间改稿：要么在应用界面里改完再导出，要么把上面那一步换成 `-f json -o 稿.json`，由 agent 这一侧的 `export` 那把 tool 出盘。**没有 `vv export` 这条子命令**，`vv` 只认 `transcribe` / `check` / `mcp`。

`vv check` 的退出码只有三个：`0` 没有 error 级结果、`1` 有（这是**判完了**，不是没跑成）、`2` 命令行或档位文件本身用不了。

## 判的是什么

### L1 结构层：会不会有一条字幕上不了屏

这一层写在代码里，改不了。判据只有一条——**会不会丢字幕**。会丢的报 error（退出码 1），只是写法不标准但照样显示的报 warn（不拦路）。

报 error：

- 解析器当场认不出的那四种块：这一条里没有一行是时间戳、时间行之前还有别的内容没被认出来、两条之间缺一个空行被并成了同一块、SRT 的时间行后面挂了位置设置（只有 VTT 才那么写）
- WebVTT 的毫秒用逗号分开——VTT 的语法只认点号，那几条浏览器整条丢
- 毫秒位数不是三位（`1,2` 是 200 毫秒不是 20 毫秒），VTT 侧
- 止点比起点早（倒挂），或起点与止点是同一个时间（零时长，一帧都不会上屏）
- 文件顺序和时间顺序反了（第 N 条比第 N-1 条开始得还早，播放器按文件顺序显示，画面会来回跳）
- 相邻两条重叠（后一条在前一条结束前就出现）
- 台词里有替换符 ``（那段字节没被认出来，多半文件不是 UTF-8）、落单代理项（半个 emoji）、C0/C1 控制字符

报 warn：

- SRT 把毫秒写在小数点后（`00:00:01.999`）——照样播，但跨软件时最容易被当成坏时间
- 没时间戳的毫秒部分（`00:00:01 --> 00:00:03`）——这条的边界最多少给一秒
- SRT 缺序号或序号不连续——libass 那一类渲染器照样逐条上屏，只有按序号配对的工具会在意
- 私有区码位（某个软件的图标字体，换个软件只剩空白）
- 时间行下面没有台词（那是一处空档，内容没坏）

### L2 排版层：阈值在档位文件里，不在代码里

六条规则，每条一个 `level`（`error` / `warn` / `info` / `off`）。内置三档：

| | `vv-default` | `broadcast-cn` | `netflix-cjk` |
| --- | --- | --- | --- |
| 每屏行数 | ≤2（info） | ≤2（error） | ≤2（error） |
| 每行字数 | ≤16（info） | ≤15（error） | ≤16（error） |
| 每条停留 | 1–7 秒（info） | 1–7 秒（error） | 0.834–7 秒（error） |
| 阅读速度 | ≤9 字/秒（info） | ≤9 字/秒（error） | ≤9 字/秒（error） |
| 相邻间隙 | off | off | off |
| 帧格对齐 | off | info | off |

- **`vv-default` 是初稿档**：L2 全 info，越线不逐条报，只在末尾一行汇总，排版那几条一个字节也不拦路（只有 L1 那种「会真丢字幕」的坏才退 1）。刚 `transcribe` 出来的稿子一条三四十个字是常态，拿交付档判它必然满屏红。**别拿它当交付判**，也别拿交付档去判初稿。
- **`broadcast-cn` 是广电对外译制口径**：每屏最多两行、出现/消失误差 ≤3 帧是那份规范里唯一两条能离线判的硬指标；**每行多少字规范没给数字**，15 是各出处里的最小值当保守线，停留秒数和阅读速度那两条规范里根本没有，抄的是 Netflix 中文指南的二手转述。
- **`netflix-cjk` 是流媒体交付口径**，⚠️ 没有一个数字是一手确认的：官方《字幕样式指南》在 partnerhelp，要合作方登录。两份二手转述一份给每行 16 字、一份给 21 字，本档取 16 当保守线。
- 报红的时候文本长这样：`第 12 条第 1 行 19 字，本档上限 15 字 —— 依据〈…〉`。**「本档上限」不是「官方红线」**，转述给用户时别把这两个词换掉；每条的完整出处在文本报告末尾那张「这一档每条阈值的来路」表里（`--json` 则是 `preset.rules`）。

### 数数的口径

- 字数按**码点**数（`[...text].length`），一个 emoji 算 1 字不算 2 字；空格与标点都算字。
- 摘掉 `<i>词</i>` 这类内联标记之后再数：上屏只有「词」两个字。
- 阅读速度数的是**上屏字符**：一条两行时，那个换行本身不上屏，不额外加字。
- 界面回执说的字数和 `vv check` 说的是同一个数（两边都调 `charCount`）。

## 三件事故意不判，别当成 bug

1. **译制稿的语言层改写（L3）不判，也不做**。规范里那四条要求——去掉标点改用半角空格断句、数字转成汉字、同一句重复三遍只上三次、删掉句头语气词——要的是**改稿**。本应用的两条底线是「不自动改稿」和「忠实转写」，这两句正面相冲；而且那四条需要 NLP，不是正则能碰的。所以这一层零覆盖：`vv check` 不会因为「数字没转成汉字」报你，它根本不看。要改就人改，或用界面里那条 AI 校对（那是另一条链路，不在这份判据里）。
2. **相邻间隙 ≥0.08 秒不判**（三档全 `off`）。应用的轴只保证「数组序＝时间序、相邻不重叠」，不保证留了间隙。打开它会把自家合法产物报成红。谁要判就在自己的档位里把 `minGap.level` 改成 `error`。
3. **「出现/消失误差 ≤3 帧」不判**。那是对着**原片**量的，SRT 文件里既没有帧率也没有参考音轨，离线判不了。只有显式给了 `--fps`，才跑得起来那一条「落点不在这一部片子的帧格上」，而且它在 `broadcast-cn` 里也只是 info：9.3 的容差本来就是三帧，半帧的格子偏移不构成越线。不给 `--fps`，这条进报告的 `skipped` 并写明理由——**「没判」和「判过」在报告里不许长得一样**。

## 自己造一档

`--preset` 也可以是一个 `.json` 路径。三条硬要求：

- **六条规则必须写全**（`linesPerCue` / `charsPerLine` / `cueDuration` / `readingSpeed` / `minGap` / `frameGrid`），少一条当场退 2 并点名缺哪条。不想判某条就把它的 `level` 写成 `off`，别整条删掉——删掉等于让「没判」和「判过」在报告里长得一样。
- 每条必须有 `cite`（短，进报错文本）和 `source`（长，进报告的出处表）。
- 数值旋钮有名册，拼错的键（`maxChars`）会被当场拒掉而不是静默不生效：`linesPerCue`/`charsPerLine` 只有 `max`，`cueDuration` 是 `min`+`max`，`readingSpeed` 是 `maxCharsPerSecond`，`minGap` 是 `min`，`frameGrid` 没有旋钮。

抄一份 `src/data/subtitle-presets/broadcast-cn.json` 改最省事。**改数字的时候把 `cite`/`source` 一起改掉**：那两条是这句话能不能站住的唯一凭据。

## 调用约定（MCP）

`vv mcp` 是一层 stdio JSON-RPC 服务，不是网络端口。挂法：

```json
{
  "mcpServers": {
    "vv": { "command": "/Applications/Vv Transcribe.app/Contents/Resources/bin/vv", "args": ["mcp"] }
  }
}
```

实现只有四个方法（`initialize` / `ping` / `tools/list` / `tools/call`，通知不回话）和三把 tool。**壳里零逻辑**：`transcribe` 和 `check` 转回同一条 `vv` 子命令，`export` 调的就是界面导出那一个函数（`exportTranscript`）。所以 agent 拿到的结论和人在终端里敲出来的一字不差，不存在第二套判据。

- `transcribe`：`{ file, format?, language?, profileId? }`。要应用开着、且 `settings.json` 根上有 `"agentApi": "on"`（改完重启应用）。**这一步决定本机多一个只绑 127.0.0.1 的监听口**，默认关。
  ⚠️ 走哪一档转写取的是**应用当时的设置**：选了云端方案，素材照旧发给那家服务商，CLI 不会比界面更本地。
- `check`：`{ file, preset?, fps? }`，回整份报告：`findings` 一条不少（L2 那条的 `message` 尾巴已经拼上「—— 依据〈cite〉」），跑过哪几条在 `checked`，阈值与完整出处在 `preset.rules`，关掉的连同为什么关掉在 `skipped`。等于 `vv check --json`。**判出红不是这把失败**——红不红看报告里的 `exitCode`，`isError` 只给「活儿没干成」（读不到文件、档位用不了、参数不合法）。
- `export`：`{ segments, format? }`，`segments` 每项 `{startTime, endTime, text}`，时间是**秒**。`transcribe` 那把 `format=json` 出来的直接能用（多出来的 `isEdited`/`isCorrected` 被忽略）。

三条别踩：

- **别自己拼 SRT**。自己拼的时间取整口径和界面不一致时，`vv check` 会报出你根本没改过的那一处。出盘走 `export`。
- **`check` 不吃素材文件**。它按字幕文件那种文本去读，超过 8MB 直接拒（那种大小不可能是字幕）。素材交给 `transcribe`。
- **改内容要一次一段**。交付档（`error`/`warn`）逐条全列：一份 300 条越线的稿子，`findings` 就是 300 条，一条不截断——这是拍板过的。两个例外要知道：`info` 级只出一行汇总（举前三例 + 总数，`vv-default` 靠这个实现「只报数不拦路」），L1 那种天生成群出现的坏法也只举前三条并点名总数。逐条改，别写个脚本把整轴的落点重排。
